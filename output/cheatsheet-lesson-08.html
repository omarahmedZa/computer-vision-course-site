Lesson 08 — Deep Learning–Based Computer Vision

Learned representations · CNN fundamentals · training basics · classical↔DL connections

Core ideas

  • Shift: hand-crafted features/pipelines → representations learned from data for a task.
  • CNNs: learn hierarchies of local filters with weight sharing (locality/translation structure). Early layers: edges/textures; deeper: larger, semantic patterns.
  • Building blocks: convolution (feature maps), nonlinearity (e.g. ReLU), padding/stride, pooling (downsample/context), normalization/regularization (as used).
  • Receptive field: input region affecting a unit; grows with depth/stride/pooling → composition from local to global.
  • Training: define loss (task-dependent), optimize by gradient descent/backprop; monitor generalization (train/val/test), address overfitting (data, augmentation, regularization).

Classical ↔ DL

  • Convolution/filters (L1): learned kernels vs fixed (Sobel/Gaussian).
  • Geometry/warping (L2,L7): spatial transformers, augmentation, but explicit warping/RANSAC still enforce geometry.
  • Features/matching (L3–L5): learned detectors/descriptors/matchers + geometric verification.
  • Blending/registration: learned alignment/compositing exist; photometric/geometric principles remain.

When classical remains valuable

  • Limited data/labels, need interpretability or guarantees.
  • Well-defined geometry/physics (calibration, planar transforms, robust fitting).
  • Resource constraints; hybrid pipelines (learned perception + model-based geometry).

Pitfalls

  • CNNs learn correlations, not guaranteed understanding; vulnerable to distribution shift.
  • Data/labels/evaluation quality drive results.
  • Don’t ignore explicit geometric constraints when they apply.
