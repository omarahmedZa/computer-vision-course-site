Unit 1 · Images as signals · Lesson 1 of 8

Introduction to Computer Vision

You can explain what computer vision is, describe the vision pipeline, and represent images as sampled/quantized signals — applying correct pixel, channel, color-space, histogram, intensity-transform, and convolution operations.

Why this matters

Computer vision turns raw pixels into measurements, descriptions, and decisions. Every later topic in this course — warping, features, fitting, blending, registration, and deep learning — begins with the same object: an image treated as a numerical signal.

If you misread what a pixel value means, which channel is which, or how a kernel is applied, the rest of the pipeline becomes confidently wrong. Understanding images as signals (with geometry and photometry you can reason about) is the foundation for both classical algorithms and modern CNNs.

H×W×Cimage tensor shape (height, width, channels)
[0, 255]common 8-bit intensity range per channel
3×3a small kernel that mixes a pixel with its neighbors

The one core idea

An image is a function sampled on a grid and quantized in value. A grayscale image can be written as I(x,y) giving intensity at spatial location (x,y); a color image gives a vector per location, e.g. I(x,y) = [R,G,B]. Most operations in vision are either point-wise (transform each pixel independently) or local/neighborhood (combine a pixel with nearby pixels via filtering/convolution).

Digital image ≈ sample(space) + quantize(intensity)

Spatial sampling sets resolution; value quantization sets bit depth. Neighborhood filtering is weighted aggregation over a local window.

How it actually works

1) What computer vision is and the vision pipeline

Computer vision (CV) seeks to extract meaningful information from images or video — e.g. detecting edges/objects, estimating motion or geometry, recognizing content, or reconstructing scenes. A typical pipeline:

StageWhat happensExamples
AcquireSensor measures light → digital image(s)camera exposure, sampling, quantization
PreprocessImprove/normalize the signaldenoise, resize, color convert, intensity adjust
Extract/computeFind structures or correspondencesedges, corners, descriptors, matches, flow
Model/estimateFit geometry or make predictionshomography, RANSAC, classification/detection
Decide/useAct on the resultalign, blend, navigate, recognize

Classical CV designs the middle stages explicitly; deep learning often learns parts of extraction/modeling from data — but both consume the same pixel signals.

2) Images as signals: sampling and quantization

A continuous scene intensity f(x,y) becomes digital by:

  • Sampling (spatial): measure at discrete grid points → resolution H×W. Coarser sampling loses fine detail (aliasing can occur if high frequencies remain).
  • Quantization (value): map continuous intensities to discrete levels. With b bits per channel there are 2^b levels (8-bit → 256 levels, typically 0–255). Coarse quantization causes banding.

Think of the image as a matrix/tensor: grayscale H×W, color often H×W×3. Each element is a sample of radiance/reflectance-related information after sensor and encoding choices.

3) Pixels, channels, and color spaces

A pixel is one grid sample; in a color image it holds multiple channels. Common representations:

SpaceChannelsIntuition / use
RGBRed, Green, BlueAdditive display-native; channels correlated with brightness and color
GrayscaleLuminance (1 channel)Intensity structure; often Y ≈ 0.299R + 0.587G + 0.114B (luma approx.)
HSVHue, Saturation, ValueSeparates color type/amount from brightness; useful for color-based segmentation intuition

RGB→Grayscale intuition: human vision is more sensitive to green; a weighted sum approximates perceived brightness. RGB↔HSV: hue encodes “which color” around a circle, saturation “how pure”, value “how bright”. Conversions are nonlinear/coordinate transforms on the same underlying color.

4) Intensity transforms and histograms

Point-wise intensity transforms map each value independently: g(x,y)=T(I(x,y)).

  • Brightness/contrast (linear): g = α·I + β (scale changes contrast/gain, offset shifts brightness). Values must be clamped to valid range (e.g. [0,255]).
  • Negative: g = L-1 - I for L levels.
  • Gamma (power-law): g = c·I^γ (on normalized [0,1]) adjusts midtones nonlinearly.
  • Thresholding (simple case): map to binary by comparing to a threshold — a decision, not just enhancement.

A histogram counts how many pixels fall into each intensity bin. It summarizes global tone/contrast (spread, peaks, clipping) but discards spatial layout — two very different images can share a histogram.

5) Filtering and convolution fundamentals (prerequisite for all later topics)

A linear filter replaces each pixel by a weighted sum of neighbors defined by a kernel (mask). For kernel K centered at (x,y):

(I * K)(x,y) = \sum_i \sum_j I(x+i, y+j)\, K(i,j)

Correlation vs convolution: convolution flips the kernel horizontally and vertically before sliding; correlation does not. For symmetric kernels (Gaussian, box) they are identical. Many libraries call correlation “convolution” in deep learning contexts — always be clear about the convention.

Boundary handling: edges need padding/extension (zero, replicate, reflect) or cropping; choices affect borders. Stride (step size) downsamples when >1.

Kernel typeExample (3×3 intuition)Effect
Box/mean blurall 1/9Averages neighbors → smoothing, noise reduction, detail loss
Gaussian blurcenter-weighted, sums to 1Smoothing with better frequency behavior/less ringing
Sharpencenter > 1, neighbors negative (e.g. [0,-1,0;-1,5,-1;0,-1,0])Amplifies local differences/edges (can boost noise)
Edge/gradient (Sobel-like)e.g. [-1,0,1;-2,0,2;-1,0,1] (x-derivative)Responds strongly to intensity changes in a direction

Why convolution matters everywhere: blur suppresses noise/high frequencies, gradients/edges highlight structure, and (as we’ll see in Lesson 8) CNNs learn kernel weights instead of hand-designing them.

Worked examples

Example 1 — Sampling and quantization intuition

A smooth 1D intensity profile is sampled at 5 positions and quantized to 3-bit values (0–7): samples [1.2, 2.9, 6.7, 6.1, 3.0] → quantized [1, 3, 7, 6, 3]. Halving the sampling rate (keep positions 1,3,5) gives [1, 7, 3], losing the dip between the two bright samples. Reducing bit depth merges nearby values (banding). Takeaway: resolution is a spatial decision; bit depth is a value-precision decision.

Example 2 — RGB to grayscale (weighted luma)

Pixel (R,G,B)=(100, 150, 200). Using Y ≈ 0.299R + 0.587G + 0.114B:

TermValue
0.299 × 10029.9
0.587 × 15088.05
0.114 × 20022.8
Y≈ 140.75 → 141

Green contributes most to perceived brightness. A naive average (100+150+200)/3 = 150 would overemphasize blue relative to perception.

Example 3 — 3×3 box blur on a center pixel

Patch: [[10,10,10],[10,50,10],[10,10,10]], box kernel all 1/9. Sum = 10*8 + 50 = 130, output = 130/9 ≈ 14.44. The bright center (50) is pulled down by darker neighbors — smoothing reduces local contrast/noise spikes.

Example 4 — Convolution vs correlation (flip matters when asymmetric)

1D signal [1,2,3], kernel [1,0,-1] (a simple derivative-like filter). Correlation at center aligns as 1*1 + 2*0 + 3*(-1) = -2. Convolution flips kernel to [-1,0,1] giving 1*(-1) + 2*0 + 3*1 = +2. The sign/orientation changes — critical for directional gradients and consistent definitions.

The trap

Common pitfalls

“A pixel is just an RGB triple.” A pixel is a sample whose meaning depends on color space, range/encoding, gamma, and channel order. RGB in one library/file may be BGR in another; values may be [0,1] floats or [0,255] uint8.

“Convolution and correlation are the same.” Only for symmetric kernels. With asymmetric/directional kernels, forgetting the flip flips the response.

“Arithmetic is always safe.” In 8-bit images, 200 + 100 can overflow/wrap in some environments or saturate in others; sharpening can push values outside range — clamp/convert types deliberately.

“Borders don’t matter.” Padding choice changes outputs near edges and can create artifacts; be explicit when results near boundaries matter.

The tell: if colors look swapped, check channel order; if gradients point the wrong way, check flip convention; if highlights turn black or noisy, check dtype/range/clipping.

Retrieval check

  1. What is the difference between spatial sampling and intensity quantization, and what visual artifact can each cause when too coarse?
    Answer

    Sampling measures the image at discrete spatial locations (resolution); too coarse loses detail and can cause aliasing. Quantization maps intensities to discrete levels (bit depth); too coarse causes banding/false contours.

  2. Why is a weighted RGB-to-grayscale conversion (e.g. luma) often preferred over a simple average?
    Answer

    Human perception is more sensitive to green and less to blue, so weighted luma better approximates perceived brightness; a simple average treats channels as equally important to luminance.

  3. Compute the output of correlating the 1D signal [2, 4, 6] (centered) with kernel [1, -1] placed so it covers [2,4] as 2*1 + 4*(-1). What does a negative result indicate?
    Answer

    2 - 4 = -2. A negative response indicates a decrease in the kernel’s direction (a downward step/change) given that kernel’s sign convention.

  4. When are convolution and correlation identical, and why do CNN libraries still need you to care about convention?
    Answer

    They are identical for symmetric kernels (e.g. Gaussian/box). You must care because asymmetric/derivative kernels differ by a flip, and “convolution” in deep learning APIs often implements correlation; consistent interpretation matters for gradients/feature orientation.

Python in Colab: implement the lesson

Run this end-to-end in Google Colab (or any Python environment with NumPy/Matplotlib). It demonstrates image representation, color conversion, histograms, intensity transforms, and convolution/correlation.

import numpy as np
import matplotlib.pyplot as plt

# 1) Image as a sampled, quantized signal (synthetic grayscale)
H, W = 64, 64
y, x = np.mgrid[0:H, 0:W]
img = (0.6*np.sin(2*np.pi*x/16) + 0.4*np.cos(2*np.pi*y/10))
img = ((img - img.min())/(img.max()-img.min()) * 255).astype(np.uint8)
print('shape:', img.shape, 'dtype:', img.dtype, 'min/max:', img.min(), img.max())

# 2) RGB channels and luma (perceived grayscale)
rgb = np.zeros((H, W, 3), dtype=np.uint8)
rgb[..., 0] = np.clip(img + 20, 0, 255)       # R
rgb[..., 1] = np.clip(img, 0, 255)            # G
rgb[..., 2] = np.clip(img//2, 0, 255)         # B
luma = (0.299*rgb[...,0] + 0.587*rgb[...,1] + 0.114*rgb[...,2]).astype(np.uint8)
naive = rgb.mean(axis=2).astype(np.uint8)

# 3) Intensity transforms: g = clip(alpha*I + beta), gamma
def linear_transform(I, alpha=1.2, beta=-10):
    return np.clip(alpha*I.astype(np.float32) + beta, 0, 255).astype(np.uint8)

def gamma_transform(I, gamma=1.5):
    In = I.astype(np.float32)/255.0
    return np.clip((In**gamma)*255, 0, 255).astype(np.uint8)

bright = linear_transform(luma, alpha=1.0, beta=40)
contrast = linear_transform(luma, alpha=1.4, beta=-30)
gamma_dark = gamma_transform(luma, gamma=1.8)

# 4) Histogram
def show_hist(ax, I, title):
    ax.hist(I.ravel(), bins=256, range=(0,255), color='#1f5f7a', alpha=0.8)
    ax.set_title(title); ax.set_xlim(0,255)

# 5) Convolution (correlation-style sliding) and a flipped kernel for true convolution
def convolve2d(I, K, flip=True):
    Kh, Kw = K.shape
    pad_h, pad_w = Kh//2, Kw//2
    Kf = np.flipud(np.fliplr(K)) if flip else K
    P = np.pad(I.astype(np.float32), ((pad_h,pad_h),(pad_w,pad_w)), mode='edge')
    out = np.zeros_like(I, dtype=np.float32)
    for i in range(I.shape[0]):
        for j in range(I.shape[1]):
            patch = P[i:i+Kh, j:j+Kw]
            out[i,j] = np.sum(patch * Kf)
    return out

box = np.ones((3,3), np.float32)/9.0
gauss = (1/16.0)*np.array([[1,2,1],[2,4,2],[1,2,1]], np.float32)
sharpen = np.array([[0,-1,0],[-1,5,-1],[0,-1,0]], np.float32)
sobelx = np.array([[-1,0,1],[-2,0,2],[-1,0,1]], np.float32)

blurred = np.clip(convolve2d(luma, box), 0, 255).astype(np.uint8)
sharp = np.clip(convolve2d(luma, sharpen), 0, 255).astype(np.uint8)
edges = convolve2d(luma, sobelx)
edges_vis = np.clip(np.abs(edges), 0, 255).astype(np.uint8)

# correlation vs convolution for an asymmetric 1D kernel (concept)
signal = np.array([1,2,3,4,3,2,1], np.float32)
k = np.array([1,0,-1], np.float32)
corr = np.array([np.sum(signal[i:i+3]*k) for i in range(len(signal)-2)])
conv = np.array([np.sum(signal[i:i+3]*k[::-1]) for i in range(len(signal)-2)])
print('1D correlation:', corr, '  1D convolution:', conv)

# 6) Visualize
fig, axs = plt.subplots(3, 4, figsize=(14,9))
axs[0,0].imshow(img, cmap='gray'); axs[0,0].set_title('Grayscale signal')
axs[0,1].imshow(rgb); axs[0,1].set_title('RGB')
axs[0,2].imshow(luma, cmap='gray'); axs[0,2].set_title('Luma (weighted)')
axs[0,3].imshow(naive, cmap='gray'); axs[0,3].set_title('Naive average')
axs[1,0].imshow(bright, cmap='gray'); axs[1,0].set_title('Bright (β=+40)')
axs[1,1].imshow(contrast, cmap='gray'); axs[1,1].set_title('Contrast (α=1.4)')
axs[1,2].imshow(gamma_dark, cmap='gray'); axs[1,2].set_title('Gamma (γ=1.8)')
show_hist(axs[1,3], luma, 'Histogram (luma)')
axs[2,0].imshow(blurred, cmap='gray'); axs[2,0].set_title('Box blur')
axs[2,1].imshow(sharp, cmap='gray'); axs[2,1].set_title('Sharpen')
axs[2,2].imshow(edges_vis, cmap='gray'); axs[2,2].set_title('Sobel X (|resp|)')
show_hist(axs[2,3], contrast, 'Histogram (contrast)')
for ax in axs.ravel():
    if ax.images: ax.axis('off')
plt.tight_layout(); plt.show()
