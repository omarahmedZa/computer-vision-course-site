Deep Learning–Based Computer Vision

You can explain CNN fundamentals and training basics, and relate learned representations to the classical CV tasks in this course.

Why this matters

Classical vision builds pipelines from hand-designed operations: filters, gradients, corners, descriptors, geometric models. Deep learning replaces (or augments) many of these with representations learned from data, often achieving strong performance when enough labeled data and compute are available.

Understanding deep learning for vision doesn’t mean forgetting the classics. Convolutions, pyramids, features, alignment, and geometry still matter: they explain what CNNs compute, how architectures are structured, and when classical methods remain the right or necessary tool.

The one core idea

A Convolutional Neural Network (CNN) learns a hierarchy of filters: early layers respond to simple local patterns (edges/textures, like Lesson 1 filters), deeper layers combine them into larger, more semantic structures because the receptive field grows. Training adjusts weights by minimizing a loss on data via gradient-based optimization.

learned convolution + nonlinearity + hierarchy = task-specific representation

CNNs generalize the filtering ideas you already know: instead of choosing a Sobel kernel, the model learns kernels that are useful for the objective.

How it actually works

1) From hand-crafted features to learned representations

Classical pipelines (e.g. detect corners/blobs → SIFT descriptor → match → RANSAC → warp) encode expert assumptions about invariance and geometry. Learning-based approaches optimize feature extraction and prediction end-to-end for a task (classification, detection, segmentation, matching), discovering which patterns matter in the data. Trade-offs: data/compute requirements, interpretability, and robustness outside the training distribution vs flexibility and performance on in-distribution problems.

2) CNN fundamentals

Convolutional layer: applies many learnable kernels over spatial locations (sharing weights across the image) to produce feature maps. Compared to fully connected layers, this exploits locality and translation structure, drastically reducing parameters.

  • Feature maps: each filter produces a response map; stacking layers builds combinations of earlier responses.
  • Padding/stride: padding controls output size/border handling; stride downsamples spatial resolution (see Lesson 1 concepts).
  • Nonlinearity: activations (e.g. ReLU) allow the network to model complex functions (a stack of purely linear convolutions would collapse to a linear map).
  • Pooling: local aggregation (max/average) reduces spatial size, adds some local translation tolerance, and increases context for later layers.
  • Receptive field: the region of the input that influences a unit’s output. Deeper units (or units after striding/pooling/larger kernels) see larger regions, enabling composition from edges → parts → objects.

3) Training basics (introductory)

Supervised learning (common case): given inputs and labels/targets, define a loss measuring prediction error (e.g. cross-entropy for classification, regression losses for coordinates). Optimization (e.g. stochastic gradient descent and variants) computes gradients of the loss w.r.t. weights (backpropagation through the network graph) and updates parameters to reduce loss.

Key practical ideas: split data (train/validation/test) to monitor generalization; overfitting occurs when the model memorizes training data — mitigated by more data, augmentation, regularization, early stopping, or architecture choices. Performance depends on data quality/coverage, labels, and compute.

4) How deep learning relates to and extends classical CV tasks

Classical topicDeep learning connection/extension
Convolution/filtering (L1)CNNs learn filter banks instead of fixed kernels; early features often resemble edges/textures.
Transforms/warping (L2)Spatial Transformer-style modules learn to warp/align; data augmentation uses geometric transforms; alignment remains critical.
Corners/blobs/SIFT (L3–L4)Learned detectors/descriptors and end-to-end matching networks replace or complement hand-crafted pipelines for robustness.
Hough/RANSAC/fitting (L5, L7)Models can regress parameters or correspondences; classical robust estimation is still used to enforce geometry or verify predictions.
Blending/registration (L6–L7)Learned alignment, stitching, and compositing models exist, but rely on geometric/photometric principles and often optimize similarity/alignment objectives.

When classical methods remain valuable: limited data/labels, need for interpretability or guarantees, well-defined geometry (calibration, SLAM components), strict resource constraints, or when the physics/geometry is known and should be enforced explicitly.

Worked examples

Example 1 — Receptive field growth

Two stacked 3×3 convolutions (stride 1): a neuron in layer 2 sees a 3×3 region of layer 1, each of which sees 3×3 of the input → total 5×5 receptive field. Add pooling/stride and deeper stacks and the field grows to cover large objects, enabling decisions based on context rather than isolated pixels (connects to “why features matter” but learned).

Example 2 — Learned edge-like filters

In a trained first convolutional layer for natural images, many kernels resemble oriented edge or color-contrast detectors — analogous in role to Sobel/Gabor-like filters from Lesson 1/3, but optimized for the downstream task and data distribution.

Example 3 — Classical + deep in registration

A modern pipeline might use a learned feature matcher to propose dense/robust correspondences, then estimate a homography with RANSAC (classical) for geometric consistency, then warp with inverse interpolation (classical). Deep components improve perception; geometric components enforce valid models.

The trap

Common pitfalls

“CNNs understand images.” They learn statistical correlations that optimize a loss on given data; they can fail on distribution shifts, spurious cues, or adversarial cases without true semantic/geometric understanding.

Ignoring data and labels: performance hinges on representative data, correct labels, and appropriate evaluation; architecture alone is not enough.

Forgetting geometry: tasks involving precise alignment, multi-view consistency, or physical constraints often benefit from explicit geometric models (transforms, RANSAC, calibration) alongside or inside learned systems.

Parameter vs. compute intuition: convolution shares weights spatially (fewer parameters than dense layers on images) but can still be computationally heavy; receptive field and resolution choices involve trade-offs.

Retrieval check

  1. What is the receptive field of a CNN unit, and why does it typically grow in deeper layers?
    Answer

    It is the region of the input image that can influence that unit’s activation. It grows with depth because each layer aggregates over a local neighborhood of the previous layer (and/or due to stride/pooling), so deeper units combine information from larger input areas.

  2. How do learned convolutional filters relate to the hand-designed kernels discussed in Lesson 1?
    Answer

    Both compute local weighted sums (filter responses) over neighborhoods. Hand-designed kernels encode fixed operations (blur, edge detection), while CNNs learn kernel weights from data to produce features useful for the training objective.

  3. Give one example of how a classical CV method remains useful in a deep learning–based vision pipeline.
    Answer

    Examples: using RANSAC to robustly estimate a homography from learned correspondences; applying geometric warping/interpolation; enforcing epipolar/planar constraints; using classical preprocessing or augmentation when appropriate.
