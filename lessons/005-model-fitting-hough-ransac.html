Model Fitting (Hough Transform, RANSAC)

You can fit lines/circles with Hough voting and estimate models robustly with RANSAC under outliers.

Why this matters

Edges and feature matches are noisy. Some points belong to the structure you want (a line, a circle, a geometric transform) and others are outliers. Least-squares fits can be pulled badly off-target by a few bad points.

Hough transforms and RANSAC are classic answers: Hough turns shape detection into voting in parameter space; RANSAC repeatedly hypothesizes a model from minimal samples and keeps the one with the most inlier support. Both ideas are central to robust geometry (including registration, Lesson 7).

The one core idea

Hough: map each evidence point to all parameter values consistent with it and accumulate votes; peaks correspond to models supported by many points. RANSAC: assume data = inliers + outliers, fit models from small random subsets, count consensus (inliers within a threshold), and return the best-supported model — trading certainty for robustness.

Hough = vote in parameter space · RANSAC = hypothesize-and-test with consensus

Both separate “explains many points” from “explains this particular noisy set,” but by different mechanisms.

How it actually works

1) Hough transform for lines

A line can be parameterized as ρ = x cosθ + y sinθ, where ρ is the perpendicular distance from origin and θ the angle of the normal. A single image point (x,y) is consistent with infinitely many lines → in (θ,ρ) parameter space it traces a sinusoidal curve.

Voting: discretize (θ,ρ) into an accumulator. For each edge point, increment all accumulator cells on its curve. Cells with many votes indicate parameters supported by many collinear points. Detect peaks to recover lines. (Slope-intercept y=mx+b is intuitive but cannot represent vertical lines cleanly; the normal form is preferred.)

2) Hough for circles (intuition)

A circle (x-a)^2 + (y-b)^2 = r^2 has three parameters (a,b,r). Each edge point votes for possible centers (and radii); with known radius it becomes a 2D vote for centers (each point votes on a circle in parameter space), and with unknown radius the accumulator becomes 3D and more expensive. More parameters → larger/sparser accumulator and more computation.

3) RANSAC (RANdom SAmple Consensus)

Algorithm sketch for fitting model M (e.g. a line needs 2 points, a homography needs 4 correspondences):

  1. Sample: randomly pick the minimal number of points to determine M.
  2. Hypothesize: fit M to that sample.
  3. Test/score: count inliers — all data points whose error/distance to M is below threshold τ.
  4. Keep best: if this consensus set is largest so far, save M (often refit on all inliers).
  5. Repeat for N iterations; return the best model.

Iteration intuition: if w is the inlier ratio and s the minimal sample size, the probability a random sample is all-inlier is w^s, so the probability of at least one good sample in N trials is 1 - (1-w^s)^N. Solve for N to reach desired confidence — more outliers or larger s means more iterations.

4) Inliers, outliers, and parameter spaces

Inliers fit the true underlying model within noise/threshold; outliers do not (mismatches, wrong structures, clutter). Hough localizes dense support in parameter space; RANSAC explicitly searches for the largest self-consistent subset. Both assume the correct model explains many points simultaneously.

Worked examples

Example 1 — Hough voting intuition

Three collinear edge points each vote along different sinusoids in (θ,ρ) space, but all three curves intersect at the same (θ*,ρ*) representing their common line. A fourth, off-line point produces a curve that may cross others but not at the same peak — the accumulator peak still identifies the dominant line.

Example 2 — RANSAC for a line

10 points: 7 lie near a line, 3 are far away. Sample 2 points: if both are inliers (likely), the fitted line passes close to the other 5 inliers → ~7 inliers total. If a sample includes an outlier, the line is skewed and gathers few inliers. After enough iterations the 7-inlier model wins and can be refit on those inliers for accuracy.

Example 3 — Iterations

Want 99% confidence, w=0.5 inliers, line needs s=2. Probability a sample is all-inlier =0.25. Need N with 1-(0.75)^N ≥ 0.99 → N ≥ log(0.01)/log(0.75) ≈ 16.4, so ~17 iterations. If w drops to 0.3, w^2=0.09 and N rises to ~49 — robustness costs iterations when outliers dominate.

The trap

Common pitfalls

Hough resolution/scale: coarse bins merge distinct lines; fine bins fragment votes and need more points/memory. Parameter range and discretization matter (and dimensionality grows with model complexity).

RANSAC threshold and iterations: τ too small rejects noisy inliers, too large admits outliers. Too few iterations can miss the correct model; degenerate samples (e.g. nearly coincident points) must be handled.

Multiple structures: a single run finds one dominant model. To find several, run sequentially removing inliers, or use multi-model variants.

Assuming inliers are a majority without checking: RANSAC works when a model has enough support, but if the true structure is weakly represented, consensus may pick the wrong thing.

Retrieval check

  1. In the Hough transform for lines, what does a single edge point contribute to the (θ,ρ) accumulator?
    Answer

    A vote along the curve of all (θ,ρ) line parameters consistent with that point (a sinusoid in normal form), rather than a single cell.

  2. Why is RANSAC robust to outliers compared with fitting a model to all points at once?
    Answer

    It fits hypotheses to minimal random subsets and evaluates them by how many points agree (inliers); outliers rarely form a larger consensus set than the true model, so the best-supported hypothesis is selected.

  3. If the inlier ratio decreases, what happens to the number of RANSAC iterations needed for the same confidence, and why?
    Answer

    It increases, because the probability w^s that a minimal sample contains only inliers drops, so more trials are required to be likely to draw at least one all-inlier sample.
